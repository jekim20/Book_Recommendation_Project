# 프로젝트 복원 및 확인 노트

이 문서는 현재 로컬 폴더에서 확인할 수 있는 자료를 기준으로 프로젝트의 코드·데이터·평가 근거를 기록합니다. 2023년 학부 프로젝트 자료와 2026년 정리 과정에서 추가하거나 수정한 내용을 구분합니다.

## 확인 범위

- 작업용 노트북: `capstone/user_based_cf.ipynb`, `capstone/matrix_factorization_lf.ipynb`
- 보존 데이터 후보: `capstone/books_review_2.csv`
- 보조 평가: `capstone/evaluate_holdout.py`
- 원본 노트북 사본: `capstone/originals/` (로컬 보관용)

현재 폴더에서 실행 코드가 확인된 추천 방식은 사용자 기반 협업 필터링과 SGD 행렬 분해입니다. 발표자료나 보고서에 나온 아이템 기반 CF, TruncatedSVD, TF-IDF, 키워드 분석, 지식 기반 추천은 대응하는 실행 코드가 확인되지 않았습니다. 구현 사실이나 모델 간 성능 비교로 소개하지 않습니다.

## 데이터 관계와 품질

| 단계 | 파일 | 확인 내용 |
|---|---|---|
| 원본 리뷰 후보 | 루트의 `Books_rating-001.csv`, `Books_rating-002.csv` | 각각 3,000,000행, 10개 열이며 서로 바이트 단위로 동일합니다. 둘을 합산하지 않습니다. |
| 전처리 리뷰 | `capstone/데이터셋/Books_rating_1.csv` | 414,548행, 9개 열 |
| 전처리 도서 메타데이터 | `capstone/데이터셋/books_data_1.csv` | 40,635행, 7개 열 |
| 모델 입력 후보 | `capstone/books_review_2.csv` | 21,538행, 14개 열, 5,070명, 1,616개 제목 |

`books_review_2.csv`의 리뷰 행은 전처리 리뷰 파일과 제목·평점·날짜·요약·본문 값이 일치했고, 제목은 전처리 메타데이터 파일에서 모두 찾을 수 있었습니다. 두 노트북도 이 파일을 입력으로 사용합니다. 따라서 현재 보유 자료에서 최종 모델 입력 후보로 판단합니다. 다만 원본 300만 행에서 각 전처리 파일을 생성한 전체 절차와 정확한 데이터 버전은 보존돼 있지 않습니다.

노트북의 `pivot_table`은 동일한 사용자-도서 조합의 평점을 평균으로 합칩니다. 21,538개 리뷰 행은 19,767개 사용자-도서 상호작용이 되고, 중복 조합 1,333개가 집계 대상입니다.

- 리뷰 행 기준 사용자별 리뷰 수의 최솟값은 1이며, 5,070명 중 1,503명은 3건 미만입니다.
- 사용자-도서 조합을 평균 집계한 뒤에는 1,951명이 서로 다른 도서 3권 미만을 평가했고, 그중 726명은 한 권만 평가했습니다.
- 발표자료에 적힌 사용자별 최소 리뷰 조건이 현재 모델 입력에 적용됐는지는 확인되지 않았습니다. 필터 조건을 임의로 추정하거나 입력 데이터를 다시 필터링하지 않았습니다.
- 책별 리뷰 행은 최소 5개입니다.
- `books_review_3.csv`는 빈 열 이름 39개와 평점 필드가 밀린 행이 확인돼 모델 입력으로 사용하지 않습니다.
- `books_new_1.csv`는 24행 중 3행이 비어 있고 나머지 대부분의 사용자 번호가 `9999`라 모델 입력으로 보지 않습니다.

## 코드 변경 내역

### 사용자 기반 협업 필터링

노트북은 사용자별 평균을 기준으로 평점을 중심화하고, 피어슨 상관계수로 이웃을 고른 뒤 아직 평가하지 않은 도서의 점수를 계산합니다. 원본 코드의 예측 가중 편차 분모는 이웃 수였는데, 가중치에 맞게 유사도 합으로 수정했습니다. 예측값은 평점 범위인 1~5로 제한합니다. 원본 저장 출력에는 5점을 넘는 점수가 있어 해당 출력은 수정된 계산을 나타내지 않습니다.

### SGD 행렬 분해

노트북은 50개 잠재 요인, 200 epoch, 학습률 0.01, 정규화 0.01 설정을 사용합니다. RMSE 계산에서 scikit-learn 의존성을 NumPy 연산으로 바꿨으며, 홀드아웃 평가 셀을 추가했습니다. 기존 저장 RMSE 로그는 학습에 사용한 관측치에서 계산돼 학습 적합도를 나타냅니다. 검증 성능으로 해석하지 않습니다.

### 보존

원본 ZIP에서 추출한 노트북 사본은 `capstone/originals/`에 유지합니다. 이 사본은 Colab 및 개인 사용자 메타데이터를 포함할 수 있어 `.gitignore`에서 공개 대상에서 제외합니다. 원본 ZIP도 공개 저장소에 올리지 않습니다.

## 2026년 재실행 및 평가

두 작업용 노트북을 현재 로컬 환경에서 처음부터 실행했습니다. 사용자 기반 노트북은 수정된 추천 결과를 출력했고, 예측 점수는 1~5 범위였습니다. 행렬 분해 노트북은 기존 SGD 학습과 추천 셀, 추가 홀드아웃 평가 셀까지 오류 없이 실행했습니다. 학습 로그의 마지막 기록된 RMSE는 190번째 반복에서 약 0.02644입니다. 이는 학습 데이터 값이며 평가 점수와 혼동하면 안 됩니다.

평가 스크립트와 노트북의 추가 평가 셀은 같은 홀드아웃 평가를 사용합니다.

| 항목 | 값 |
|---|---:|
| 입력 리뷰 행 | 21,538 |
| 평균 집계 후 사용자-도서 조합 | 19,767 |
| 중복 사용자-도서 조합 | 1,333 |
| 학습 / 검증 상호작용 | 15,423 / 4,344 |
| 검증 사용자 / 도서 | 4,344 / 1,351 |
| 분할 시드 / 모델 초기화 시드 | 42 / 1 |
| 행렬 요인 수 / epoch | 50 / 200 |

두 권 이상 평가한 사용자마다 한 건을 검증용으로 남겼고, 모든 검증 도서가 학습 데이터에도 남도록 구성했습니다. 단일 상호작용 사용자는 학습 세트에만 둡니다.

| 예측 방식 | RMSE | MAE |
|---|---:|---:|
| 전체 학습 평점 평균 | 1.0753 | 0.8542 |
| 사용자별 학습 평점 평균 | 1.1647 | 0.7902 |
| 행렬 분해 원점수 | 1.9509 | 1.6157 |
| 행렬 분해 점수를 1~5로 제한 | 1.9019 | 1.5873 |

이 분할에서 행렬 분해는 두 평균 기준선보다 낮은 성능을 보였습니다. 원점수 예측 범위는 약 -1.431~5.456이었습니다. 이 평가는 한 번의 고정 분할만 사용하며, 여러 시드 평균이나 사용자 기반 CF와 동일 조건 비교는 포함하지 않습니다.

평가 스크립트는 Python 표준 라이브러리 난수 초기화를 사용합니다. 따라서 시드와 모델 구조는 기록돼 있지만, 2023년 노트북의 NumPy 초기 배열과 비트 단위로 같다고 볼 수 없습니다. 이 결과는 2026년에 수행한 신규 분석이며 2023년 결과가 아닙니다.

## 실행 방법

저장소 루트에서:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r capstone/requirements.txt
python capstone/evaluate_holdout.py
```

노트북은 VS Code에서 열고 `.venv` 커널로 실행합니다. 입력 CSV는 `capstone/books_review_2.csv`에 있어야 합니다. 노트북은 작업 폴더 루트 또는 `capstone/`에서 파일을 탐색합니다.

2026년 확인 환경은 Python 3.11.15, NumPy 2.4.6, pandas 3.1.1, ipykernel 7.4.0입니다. `capstone/requirements.txt`는 설치 의존성 목록일 뿐 버전 잠금 파일이 아닙니다. 2023년 Colab 환경 정보는 확보하지 못했습니다.

## 공개 전 남은 일

1. 공개할 데이터의 원본 출처, 버전, 라이선스 및 재배포 가능성을 확인합니다. 확인 전에는 원본·전처리 CSV 및 ZIP을 커밋하지 않습니다.
2. 사용자별 최소 리뷰 필터가 적용된 시점과 기준을 원본 기록에서 확인합니다.
3. 아이템 기반·TF-IDF·지식 기반 방법을 포트폴리오에서 구현 사실로 소개하려면 해당 코드와 평가 근거를 추가로 찾습니다.
4. 결과를 강한 성능 주장으로 활용하려면 여러 분할에서 평가하고 사용자 기반 CF도 같은 데이터 분할·지표로 비교합니다.
5. 공개 전 노트북 출력과 문서에 개인 이름, 학번, 로컬 경로 또는 사용자 식별 메타데이터가 남지 않았는지 다시 살펴봅니다.

현재 프로젝트 폴더가 독립 Git 저장소의 루트입니다. `.gitignore`는 이 저장소 안의 데이터와 개인 자료를 제외합니다.
